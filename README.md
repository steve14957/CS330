1. How do I approach designing software?

     Throughout this course, I learned that designing software requires planning, organization, and the ability to adapt when something does not work as expected.  Working on my 3D scene helped me develop a better understanding 
of how individual objects, textures, lighting, and camera controls work together to create a complete visual environment.  One of the most important skills I developed was learning to break a complicated project into smaller,
manageable tasks rather than trying to complete everything at once.

     My design process involved building the basic scene first and then gradually improving it throughout the course milestones.  I worked on object placement, transformations, textures, camera movement, and different
lighting techniques.  As I added new features, I tested them to make sure they worked correctly with the existing scene.  This approach allowed me to identify problems early and make adjustments without having to redesign
the entire project.  I can apply this same process to future software projects by establishing a solid foundation, developing features in stages, and continuously evaluating the results.

3. How do I approach developing programs?

     My approach to developing programs has evolved throughout this course.  Before working with OpenGL, I had limited experience creating interactive 3D environments.  As I progressed through the milestones, I became more 
comfortable working with C++, understanding how the rendering process works, and making changes to existing code.  I learned how to implement textures, adjust camera movement using keyboard and mouse input, and configure 
directional, point, and spotlight lighting to improve the appearance of my scene.

     Iteration played an important role in completing this project.  Many features required multiple adjustments before they worked the way I intended.  For example, I had to make changes to the mouse scroll behavior,
experiment with lighting positions and intensities, and troubleshoot issues involving shaders and texture files when preparing the final executable.  Each challenge helped me become more comfortable debugging and testing
my code.  Throughout the milestones, my development approach became more organized and methodical.  Instead of making several changes at once, I learned to focus on individual problems, test possible solutions, and verify
that everything continued to function correctly.
